# Чек-лист по User Flow

## Область проверки

- Сценарий: неавторизованный пользователь открывает карточку навыка и из этого контекста попадает в auth-flow (`login/register`).
- Цель: при закрытии auth-экрана и при успешной авторизации пользователь возвращается на ту же карточку навыка, а не на главную.

## Чек-лист (редирект auth -> skill)

- [pass] Открыть `/skill/:skillId/:userId` как гость -> нажать `Войти` в хедере -> нажать `Закрыть` на auth-экране -> возврат на ту же карточку навыка.
- [pass] Открыть `/skill/:skillId/:userId` как гость -> нажать `Зарегистрироваться` в хедере -> нажать `Закрыть` на auth-экране -> возврат на ту же карточку навыка.
- [pass] Открыть `/skill/:skillId/:userId` как гость -> нажать `Предложить обмен` -> из модалки перейти в `Войти` -> нажать `Закрыть` -> возврат на ту же карточку навыка.
- [pass] На `LoginPage` нажать `Зарегистрироваться`, затем `Закрыть` -> цель возврата из исходной карточки навыка сохраняется.
- [pass] Успешный вход из контекста карточки навыка редиректит на ту же карточку (`state.from` учитывается).
- [pass] Успешная регистрация (`register -> step2 -> step3`) из контекста карточки навыка редиректит на ту же карточку (`state.from` учитывается).

## Поведение fallback

- [pass] Если `state.from` отсутствует или невалиден, fallback-редирект остаётся дефолтным (`/`), что сохраняет обратную совместимость.
